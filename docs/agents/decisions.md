## 2026-11-11 — ZCode desktop startup repaired by .recover on tasks-index.sqlite
- Symptom: ZCode 3.18.0 desktop "Startup preparation failed … database appears damaged", diagnostic 2957a09c; every retry failed in ~90 ms at startup stage 9.
- Diagnosis: telemetry showed `database_startup_baseline:tasks-index`; extracted app.asar to confirm host storage = `~/.zcode/v2/tasks-index.sqlite` (prepared by worker `prepareTasksIndexStorage`), session storage = `~/.zcode/cli/db/db.sqlite` (prepared per workspace via `Resources/glm/zcode.cjs app-server --stdio --prepare-storage`, which passed cleanly when run manually). quick_check proved tasks-index damaged; db.sqlite integrity ok. Initial confusion: the two sqlite files were checked in one batch and the error was attributed to db.sqlite; recheck with app closed settled it.
- Decision: repair in place instead of contacting support or deleting. Quit app → `cp` backups → `sqlite3 <bak> .recover | sqlite3 new` → quick_check ok → re-insert 3 `session_creation_commands` rows from `lost_and_found` (session→task bookkeeping only; all 182 tasks survived) → swap in → relaunch → startup attempt `ea384d0b` ready.
- Kept on disk: damaged original `~/.zcode/v2/tasks-index.sqlite.bak-corrupt-20261111-1247` (3.6 MB, for support); healthy 990 MB `~/.zcode/cli/db/db.sqlite.bak-corrupt-20261111-1240` (redundant, deletable).
